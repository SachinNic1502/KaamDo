# Security audit

Repository source assessment, 2026-09-21. No exploitation against a deployed service was performed. TASK IDs link findings to the implementation register. Severity reflects the observed reachable logic if deployed, not an assertion of existing compromise.

| Task / priority | Evidence | Impact / required control |
| --- | --- | --- |

| 002 P0 | payments POST creates completed Payment and eligible Payout without provider call/signature; mobile verification errors swallowed | Fabricated paid jobs/earnings; retries can duplicate or leave partial records. Server price calculation, provider order/signature/webhook verification, idempotency and atomic ledger writes. |
| 003 P0 | jobs/projects PATCH, attendance POST/PATCH, disputes POST, payment-methods DELETE lack resource ownership | Cross-account business changes/deletion; wage approval by ordinary users. Enforce resource policy in scoped query and check role/assignment. |

The token cookie path alone does not prove an exploitable CSRF issue: no cookie-setting login was found. Bearer requests and cookie authentication have different threat models. Likewise, this audit found no confirmed SQL injection (the datastore is MongoDB), dangerous HTML rendering sink, eval-based execution or unsafe redirect flow. These are coverage observations, not security guarantees. No claim is made that stripping `<`/`>` or SQL keywords is an adequate injection defense.

Uploads: direct unsigned Cloudinary preset is public client configuration, with provider restrictions unknown. The alternate users POST upload endpoint does not exist and tries to JSON-serialize FormData. Require authenticated signed uploads, size/type/content checks, private KYC access, scoped download URLs and retention policy. TASK-018/029.

Secrets/configuration: inspected environment variable names and code references without publishing local values. JWT secrets now have no hardcoded fallback. No verified live provider private key was identified in inspected source. The known seed credential is development code with a production risk, not evidence that a deployed account uses it. Audit repository history and built artifacts separately before release; do not treat a clean current-source scan as a historical secret scan.

Rate limiting exists **only where authRateLimit is invoked**. It uses process memory and combines forwarded-IP headers with a caller-controlled user agent. Changing user agent changes bucket; untrusted forwarding headers and multiple instances require deployment-aware treatment. Redis presence does not make this limiter distributed. API limiter helpers are not wired across business routes.

Security test acceptance: two users per non-admin role and an admin; owner/non-owner IDs; disabled/deleted/role-changed sessions; unauthorized field updates; OTP concurrent reuse/exhaustion; financial webhook replay/signature tamper; upload type/size/ownership; post-logout cache isolation. Use isolated fixtures only. Restore backup before migrations and retain redacted test evidence. Registry audits returned zero advisories for both lockfiles; authorization flaws remain regardless of this result.
